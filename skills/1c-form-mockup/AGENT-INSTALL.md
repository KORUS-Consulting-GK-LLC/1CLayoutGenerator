# Подключение 1c-form-mockup: инструкция для агента

Выполни эту инструкцию, когда пользователь поручил установить или подключить
приложенный пакет `1c-form-mockup`. Она описывает установку, а не генерацию
пользовательского макета. Рабочий процесс генерации находится в `SKILL.md`.

## 1. Определи место установки

Сначала установи, в каком проекте и harness работаешь. Прочитай существующие
инструкции проекта и настройку загрузчика skills. Если пользователь указал
путь или область установки — используй их.

- **ZCode в проекте:** `<project>/.zcode/skills/1c-form-mockup/`.
- **Codex, пользовательская установка:** `$CODEX_HOME/skills/1c-form-mockup/`,
  если CODEX_HOME задан; иначе `~/.codex/skills/1c-form-mockup/`.
- **Иной harness:** используй его фактически настроенный каталог skills.
  Не считай `.zcode` универсальным путём и не придумывай имя конфигурационного
  параметра загрузчика.
- **Загрузчика skills нет или его способ подключения неизвестен:** сохрани
  пакет в согласованном каталоге инструментов проекта, прочитай `SKILL.md` и
  используй CLI по абсолютному пути. Сообщи, что доступен ручной вызов, а
  автоматическое обнаружение skill не настроено.

Обозначения ниже: `<skill-dir>` — каталог с установленным `SKILL.md`,
`<workspace>` — рабочая папка пользователя. Не вставляй эти обозначения
буквально в команды. Учитывай пробелы и кириллицу в путях.

## 2. Проверь и установи пакет

1. Если получен ZIP, распакуй его в отдельную временную папку. Не допускай
   выхода записываемых путей за её пределы. Найди единственный каталог
   `1c-form-mockup`, содержащий `SKILL.md`, `MANIFEST.json` и `scripts/`.
2. Найди Python3.9+ и запиши его фактический executable/version. Runtime не
   требует pip-пакетов, Node.js, MCP или сервера1С.
3. Проверь распакованную копию:

   ```text
   python "<unpacked-skill>/scripts/verify_package.py" "<unpacked-skill>"
   ```

   Нужны exit0 и JSON `passed: true`. При несовпадении SHA останови установку
   и укажи файл ошибки; не переписывай manifest под повреждённое содержимое.
4. Скопируй **весь каталог skill**, включая assets/references/scripts/agents/tests
   и manifest. Не копируй только `SKILL.md`. Итог должен быть
   `<skill-dir>/SKILL.md`, а не двойной вложенный каталог.
5. Если такая установка уже существует, сравни manifest и файлы. Совпадающую
   не переустанавливай. Локальные правки сохраняй: при конфликте подготовь
   новую версию рядом и сообщи, какие файлы расходятся, вместо слепой замены.
6. Повтори проверку SHA уже в месте установки.

`agents/openai.yaml` — дополнительные UI-метаданные; другой harness может их
игнорировать. `SKILL.md` и CLI не зависят от этого файла.

## 3. Подключи к агенту

Прочитай установленный `SKILL.md` и проверь, что ссылки на references/assets
доступны по фактическому пути. Если harness умеет обнаруживать skills,
используй его штатный механизм обновления/перечитывания каталога. Не объявляй
skill автоматически загруженным только потому, что файлы скопированы.

Если нужен адаптер-инструкция для среды без загрузчика, достаточно такого
фрагмента в её существующем документе инструкций. Подставь реальный путь и
добавь фрагмент без замены остальных правил, только в пределах поручения:

```text
Для HTML-макетов управляемых форм1С используй skill 1c-form-mockup.
Перед работой прочитай <skill-dir>/SKILL.md.
CLI: python <skill-dir>/scripts/form_html.py.
Передавай реальный --src и отдельный --configuration для каждого источника.
Результат — визуальное предложение, не изменённая форма в базе1С.
```

Если изменение общего документа инструкций не входит в поручение, не меняй
его: отдай этот фрагмент и используй явное чтение skill в текущей задаче.

## 4. Проверь запуск без интерфейса

Из `<workspace>` создай отдельный каталог, например `mockups/install-check`.
Запусти установленную копию:

```text
python "<skill-dir>/scripts/form_html.py" --help
python "<skill-dir>/scripts/form_html.py" render --json "<skill-dir>/assets/example.form.json" --data "<skill-dir>/assets/example.data.json" --out "<workspace>/mockups/install-check/example.html"
```

Нужны exit0, JSON с путём `html`, существующий непустой HTML и отсутствие
`warning`. Исходные файлы skill должны остаться неизменными. Проверяй команды
из рабочей папки, чтобы случайная зависимость от CWD/каталога установки не
скрыла проблему.

Для этой проверки **не передавай `--open` или `--png`** и не запускай браузер.
Chrome не является условием готовности HTML. По отдельному поручению backend
можно проверить `python -m unittest discover -s "<skill-dir>/tests" -v`;
тест реального браузера по умолчанию пропускается.

## 5. Сообщи результат

Кратко укажи:

- версию пакета, фактический `<skill-dir>` и harness;
- Python executable/version и результат проверки SHA;
- путь проверочного HTML и результат запуска;
- статус: автоматическое обнаружение подтверждено либо доступен только
  явный вызов/чтение SKILL.md;
- PNG не проверялся, если браузер не запускался.

Подключение не требует модели/API-ключа, настройки СППР или изменения конфигурации
1С. Пользовательские XML/профили и результаты хранятся в рабочем проекте, не
в установленном skill.

## Готовое поручение для передачи другому агенту

> Установи приложенный пакет `1c-form-mockup` в моей текущей среде. Найди внутри
> `AGENT-INSTALL.md`, выполни его и проверь пример без открытия браузера и PNG.
> Сохрани существующие настройки и локальные изменения. В результате укажи путь
> установки, способ вызова и подтверждён ли автоматический доступ к skill.
